# Design

## Frame layer

`MAVLink` (`src/mavlink.ads`) holds the types and the checksum:
CRC-16/MCRF4XX (X.25) from `16#FFFF#`, over the frame after the start byte
up to the payload's end, then over the message's CRC_EXTRA byte.

`MAVLink.Frames` parses and encodes v2 frames:

- `Push` takes one byte at a time with bounded work per byte and keeps one
  frame. It reports `Message_Ready` for a known message with a correct
  checksum; `Received` then holds the header, the received length and the
  payload, zero after the received bytes, so a codec reads fields at fixed
  offsets whether or not the sender truncated them. It also reports
  `Bad_Checksum`, `Unknown_Message` (an ID this build does not know: its
  checksum cannot be checked) and `Unsupported_Flags` (a signed frame, read
  to its end, or an incompatibility flag it does not know), and counts each
  with the bytes skipped outside frames. v1 frames (`16#FE#`) are skipped.
- `Encode` builds an unsigned frame from a header and a full payload,
  dropping the payload's trailing zero bytes and keeping at least one, as
  the specification requires of senders.

`MAVLink.Dialect` lists the messages this build knows with their CRC_EXTRA
and full payload length. It is generated with the message packages.

## Messages

Each message is a child package of `MAVLink.Messages`, generated from the
MAVLink XML definitions: the message's `Id` and payload `Length`, a
`Content` record of its fields, `Pack` (record to payload, in wire order)
and `Unpack` (received message to record). [messages.md](messages.md) lists
the messages built; `generator/messages.txt` selects them.

```ada
Frames.Encode
  (Head    => (Sequence => Seq, System => 1, Component => 1,
               Id => Messages.Attitude.Id, Compat_Flags => 0),
   Payload => Messages.Attitude.Pack (Now),
   Frame   => Frame,
   Last    => Last);
```

How the definitions map to Ada:

- Fields keep their names in Ada case (`time_boot_ms` is `Time_Boot_Ms`).
  A name that is an Ada reserved word gets `_Field` (HEARTBEAT's `type` is
  `Type_Field`).
- Integer fields are the `Interfaces` type of their size and signedness;
  `char` is `Unsigned_8`.
- `float` and `double` fields are `Float_Bits` and `Double_Bits`, their
  IEEE 754 bits. MAVLink sends NaN for "unknown" in many fields, and a
  SPARK `Float` cannot hold NaN, so the record keeps the bits:
  `MAVLink.Floats.Is_Finite` says whether a field holds a value, and
  `To_Float` / `To_Bits` convert finite ones.
- Arrays of 8-bit elements (`char[50]`, `uint8_t[n]`) are `Byte_Array`
  subtypes; others get an array type of their own. Text fields are bytes,
  not `String`: the specification does not guarantee a NUL terminator.
- Extension fields are part of the record; a sender that predates them
  sends none, and they unpack as zero.
- Enumerations (`MAV_TYPE`, `MAV_CMD`, ...) are plain integers; the field's
  comment names the enumeration.

## Generator

`generator/adamavlink_gen.py` (`make generate`) reads
`definitions/common.xml` with its includes and writes `MAVLink.Dialect`, the
message packages and `docs/messages.md`. It uses only the Python standard
library and is written from the serialization specification: wire order
(base fields by element size, largest first, stable; then extensions in
definition order), CRC_EXTRA (over the message name and the base fields'
types and names, with array lengths) and payload lengths. `make
check-generated` regenerates and fails if the committed code differs.

## What is proved

`make prove` runs GNATprove (level 2, every check an error) over every unit
in `src`, generated ones included: absence of run-time errors (no index,
range, overflow or division failure, for any input byte sequence) and the
stated preconditions at each call.

Not proved:

- The body of `MAVLink.Floats` is outside SPARK: the provers do not model a
  float's bits. It is four unchecked conversions; compile-time checks
  require `Float` and `Long_Float` to be IEEE single and double precision.
- Functional correctness: that `Encode` and `Push` agree, that the CRC is
  MCRF4XX, that each message's layout matches the definition. The tests
  check those against pymavlink, an independent implementation.

## Verification

- `tests/src/test_mavlink.adb`: the CRC's check value (`123456789` gives
  `16#6F91#`); HEARTBEAT frames from pymavlink, full and truncated to one
  payload byte, encoded and parsed; noise and v1 bytes before a frame, a
  damaged payload, an unknown message ID, a signed frame, an unknown flag,
  and recovery after each; signed field extremes; float conversions, NaN
  and infinity.
- `tests/src/test_messages.adb`, generated by
  `tests/vectors/generate_messages.py` (`make vectors-messages`): every
  generated message with pseudo-random values in every field, encoded by
  pymavlink. `Pack` and `Encode` must give pymavlink's bytes, and `Push`
  and `Unpack` the content back. The script also checks each CRC_EXTRA and
  payload length against pymavlink's.

`make test` runs both with GNAT 16.1, `make test-gnat14` with GNAT 14.2.

## Roadmap

1. The parameter protocol messages (PARAM_REQUEST_LIST, PARAM_REQUEST_READ,
   PARAM_SET, PARAM_VALUE) and others as users need them: a line in
   `generator/messages.txt` each.
2. Enumeration constants from the definitions.
3. Signature checking (optional, per link).
